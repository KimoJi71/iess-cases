# 戰情室 - 維修服務 Demo 設計文件

**日期：** 2026-07-09
**範圍：** 簡易可操作前端 demo（記憶體假資料，重整後重置）
**風格：** 戰情室深色監控風格
**技術：** 原生 HTML / CSS / JS，免建置，可擴充模組結構

---

## 1. 目標與成功標準

提供可直接開啟的靜態頁面，演示「戰情室 → 維修服務」案件管理流程，包含：

- 案件列表（篩選、燈號、操作）
- 新增叫修單
- 查看／編輯案件（含 QR 掃描解鎖處理資訊）
- 案件結案確認
- 複製案件 URL

成功標準：雙擊 `index.html` 即可操作上述流程；之後新增第一／二層功能時，只需擴充導覽設定與對應 module，不必重寫殼層。

---

## 2. 檔案結構

```
index.html              # 殼：header + sidebar + 內容掛載點
css/
  styles.css            # 戰情室深色主題與共用元件樣式
js/
  app.js                # 導覽切換、模組掛載
  data.js               # 假資料、下拉選項、客戶／門市對照
  modules/
    maintenance.js      # 維修服務（列表、新增、編輯、結案）
```

之後擴充時：在 header／sidebar 註冊新項目，並新增 `js/modules/<feature>.js`。

---



## 3. 版面與導覽

```
┌─────────────────────────────────────────────────────┐
│  Header（第一層功能）                                  │
│  系統名 | [戰情室] [其他…]                              │
├──────────┬──────────────────────────────────────────┤
│ Sidebar  │  Main Content                             │
│（第二層） │  依選中功能渲染 module                       │
│ 維修服務  │                                            │
└──────────┴──────────────────────────────────────────┘
```

- Header 固定；目前僅「戰情室」為 active。其他第一層功能可先不顯示，或顯示為 disabled 佔位。
- Sidebar 僅在「戰情室」底下顯示；目前僅「維修服務」。
- Main 可捲動；預設路由：戰情室 → 維修服務 → 案件列表。

## 4. 案件列表



### 4.1 預設行為

- 進入維修服務即顯示列表
- 預設只顯示「未結案」案件
- 叫修日期由新到舊排序
- 無資料時顯示「無資料」
- 表格欄位多，支援橫向捲動



### 4.2 頂部操作列

- **左側篩選（處理狀態，含數量）：** 待料、待報價、待汰換、轉原廠、其他
  - 點選套用篩選；再點同一項取消，回到全部未結案
- **右側：**「新增叫修單」按鈕



### 4.3 表格欄位


| 欄位   | 說明                                                     |
| ---- | ------------------------------------------------------ |
| 操作   | 編輯、案件結案、複製 URL                                         |
| 燈號   | 紅=工項分類為緊急叫修黃=超過預計日期尚未完成綠=處理狀態為案件完成其他不顯示燈號           |
| 叫修日期 | YYYY-MM-DD                                             |
| 案件編號 | 格式：年月日+序號，例如：20260709001                               |
| 客戶名稱 | 例如：星巴克、屈臣氏、萊爾富                                         |
| 門市名稱 | 例如：台北信義店                                               |
| 行政區域 | 北區 / 中區 / 南區 / 東區                                      |

| 叫修項目 | 室內機 / 室外機 / 風管 / 出風口 / 控制面板 / 跳代碼 / 空氣門                |
| 叫修原因 | 不冷 / 異音 / 溫控故障 / 跳機 / 異味 / 漏水 / 代碼 / 其他                |
| 故障描述 |                                                        |
| 實際原因 |                                                        |
| 指派人員 | A~D組 / 晉詮人員 / 協力廠商 / 案件待辦                              |
| 案件狀態 | 已派工=有指派人員、預計日期、預計時間未派工=沒有指派人員、預計日期、預計時間已完成=處理狀態為案件完成 |

約 8～12 筆，涵蓋各處理狀態與燈號，方便 demo。

## 5. 新增叫修單

以 Modal 呈現，欄位如下：


| 欄位   | 型態／規則                          |
| ---- | ------------------------------ |
| 工項分類 | 下拉：一般、緊急、保養、其他                 |
| 客戶名稱 | 下拉或可選清單                        |
| 門市名稱 | 依客戶連動；選後自動帶入門市地址、服務等級          |
| 叫修人員 | 下拉或可選清單                        |
| 叫修項目 | 下拉：室內機、室外機、風管、出風口、控制盤、訊號碼、風簾等  |
| 叫修原因 | 下拉：不冷、噪音、燈號異常、跳電、異味、漏水、錯誤代碼、其他 |
| 故障描述 | 文字區；叫修原因為「其他」時必填               |
| 指派人員 | 下拉：A~D組、晉詮人員、協力廠商、案件待辦         |
| 預計日期 | 日期                             |
| 預計時段 | 時段區間                           |


儲存後寫入記憶體陣列、關閉 Modal、重新渲染列表。

## 6. 查看／編輯案件

以較大 Modal 呈現，分三段：

### 6.1 案件資訊

同新增欄位，可編輯。

### 6.2 設備資訊

- 「掃描設備 QR CODE」按鈕（demo：點擊即模擬掃描成功）
- 掃描後顯示：客戶、門市、設備區域、室內／室外、機型



### 6.3 處理資訊

- **未掃描前鎖定（disabled）**
- 實際原因（文字）
- 處理方式：動態列，每列含大分類／中分類／小分類／數量，可新增／刪除
  - 大分類示例：人工、零件、材料、特殊工
  - 中分類示例：分離式、冰水機、其他
  - 小分類：依 demo 提供固定選項即可
- 備註
- 處理狀態：待料、待報價、尚未完成、轉原廠、轉汰換、案件完成

儲存後更新該筆案件並刷新列表。

## 7. 案件結案與複製 URL



### 7.1 結案

- 列表「案件結案」→ 確認對話框
- 確認後標記 `closed: true`（或等價狀態），從預設未結案列表移除
- Demo 不另做「案件審核」列表頁（需求文件有提及，本階段刻意省略）



### 7.2 複製 URL

- 複製該案件假連結（例如 `https://demo.local/cases/{案件編號}`）到剪貼簿
- 短暫提示「已複製」

## 8. 視覺風格

- 深色背景（戰情室／監控感）
- 狀態燈號紅／黃／綠醒目
- Header、Sidebar 固定；主內容區可捲動
- 表格、按鈕、Modal 對比清楚，適合投影／現場 demo
- 不追求完整設計系統；樣式集中於 `styles.css`

---



## 9. 資料與狀態

- 所有案件存在記憶體陣列（`data.js` 初始資料 + runtime 變更）
- 重整頁面後重置
- 不使用 localStorage、不接後端 API
- 篩選狀態、目前開啟的 Modal／編輯中案件 ID 由 `maintenance.js` 管理

---



## 10. 明確不在範圍

- 後端、登入、權限
- localStorage 持久化
- 案件審核列表頁
- 真實 QR 掃描（相機）
- 響應式手機版完整適配（以桌面 demo 為主，基本可用即可）
- 其他第一／二層功能的實際內容（僅預留擴充點）

---



## 11. 擴充約定

新增功能時：

1. 在 `app.js`（或導覽設定）註冊第一層／第二層項目
2. 新增 `js/modules/<name>.js`，匯出 `mount(container)` / `unmount()`（或等價介面）
3. 共用樣式放 `styles.css`；功能專屬樣式可後續再拆檔
