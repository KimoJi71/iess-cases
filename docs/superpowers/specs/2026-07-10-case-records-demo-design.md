# 戰情室 - 維修服務 - 叫修案件紀錄 Demo 設計文件

**日期：** 2026-07-10
**範圍：** 於既有 demo 新增第三層功能「叫修案件紀錄」（記憶體假資料，重整後重置）
**風格：** 沿用既有戰情室主題與共用元件
**技術：** 原生 HTML / CSS / JS，免建置，延續現有模組結構

---

## 1. 目標與成功標準

在現有「戰情室 → 維修服務」下，新增**第三層功能**「叫修案件紀錄」，提供：

- 依日期區間查詢的案件列表（唯讀）
- 點選單筆查看案件明細（唯讀，不可編輯）

成功標準：

- 導覽出現三層結構：戰情室（第一層）→ 維修服務（第二層）→ 叫修案件紀錄（第三層）
- 進入頁面預設查詢「當日」案件並顯示列表
- 可依開始／結束日期篩選；無資料顯示「無資料」
- 列表包含「未結案」與「結案」案件
- 點「查看」開啟明細，內容不可編輯
- 不改動、不破壞既有「叫修案件」（原 MaintenanceModule）功能

## 2. 檔案結構與改動

```
index.html                  # 新增載入 js/modules/case-records.js
css/styles.css              # 新增第三層導覽、明細、日期篩選樣式（沿用既有變數）
js/
  app.js                    # 導覽由兩層擴充為三層（第二層可含子項）
  data.js                   # 不變，沿用 SEED_CASES 與選項
  modules/
    maintenance.js          # 不變
    case-records.js          # 新增：叫修案件紀錄（列表 + 明細）
```

- **導覽調整原則：** 第二層「維修服務」由「直接掛載模組」改為「可含第三層子項」。
  - 子項一：`叫修案件` → `MaintenanceModule`（既有功能，等同原本維修服務畫面）
  - 子項二：`叫修案件紀錄` → `CaseRecordsModule`（本次新增）
- `app.js` 需支援：若第二層有 `children` 則渲染第三層並掛載對應第三層模組；否則維持原本行為（向下相容）。

## 4. 叫修案件紀錄 - 案件列表

### 4.1 預設行為

- 進入頁面：預設查詢「當日」案件（開始日期＝結束日期＝今天）並顯示列表
- 叫修日期由新到舊排序
- **列表同時包含「未結案」與「結案」案件**（與「叫修案件」不同，本頁不隱藏已結案）
- 無符合條件時，列表顯示「無資料」
- 欄位多，支援橫向捲動（沿用 `.table-wrap` / `.data-table`）

### 4.2 頂部篩選列

| 欄位   | 型態／規則                    |
| ---- | ------------------------ |
| 開始日期 | 日期選擇器，格式 `YYYY-MM-DD`    |
| 結束日期 | 日期選擇器，格式 `YYYY-MM-DD`    |
| 搜尋   | 按鈕；點擊後以日期區間過濾列表          |

- 進入時兩個日期預設為今天，並自動查出當日案件。
- 過濾邏輯：`開始日期 <= 叫修日期 <= 結束日期`（含端點）。
- 未填其中一端時，該端視為不限制（demo 容錯）。

### 4.3 列表欄位

| 欄位   | 說明                                          |
| ---- | ------------------------------------------- |
| 操作   | 「查看」按鈕 → 開啟明細                               |
| 叫修日期 | `YYYY-MM-DD`                                |
| 案件編號 | 年月日+序號，例如 `20260708001`                     |
| 客戶名稱 | 星巴克 / 屈臣氏 / 萊爾富                              |
| 門市名稱 | 例如 台北信義店                                    |
| 行政區域 | 北區 / 中區 / 南區 / 東區                           |
| 工項分類 | 一般叫修 / 緊急叫修 / 保養清潔 / 其他                     |
| 叫修項目 | 室內機 / 室外機 / 風管 / …                          |
| 叫修原因 | 不冷 / 異音 / …                                 |
| 故障描述 | 文字                                          |
| 實際原因 | 文字                                          |
| 指派人員 | A~D組 / 晉詮人員 / 協力廠商 / 案件待辦                   |
| 案件狀態 | `結案`（closed=true）／`未結案`（closed=false）       |

> 註：需求文件的「案件狀態」欄在本紀錄頁以「未結案／結案」呈現，符合「包含未結案、結案之案件」的描述。

## 5. 查看案件明細（唯讀）

- 由列表「查看」按鈕開啟 Modal，帶入該案件資料。
- **全部欄位不可編輯**（純顯示，無輸入元件、無儲存按鈕，只有關閉）。
- 分三段呈現：

### 5.1 案件資料

案件編號、工項分類、叫修人員、客戶名稱、門市名稱、服務等級、門市地址、叫修項目、故障描述、叫修原因

### 5.2 設備資料

客戶名稱、門市名稱、設備區域、內／外、型號

- 若該案件尚未掃描設備（`equipment` 為 null），顯示「尚無設備資料」。

### 5.3 處理資料

實際維修原因、處理方式（大／中／小分類＋數量列表）、備註、處理狀態
（待料／待報價／尚未處理完成／轉原廠／轉汰換／案件完成）

- 若無處理方式列，顯示「無處理方式」。

## 6. 資料來源與狀態

- 本頁為唯讀，直接讀取 `AppData.SEED_CASES`（透過 `createCaseStore` 建立唯讀讀取）。
- 與「叫修案件」各自持有 store 實例；demo 階段不共享 runtime 變更（重整後兩者皆重置為 seed）。
- 篩選日期區間、目前開啟的明細案件 ID 由 `case-records.js` 內部管理。

> 註：既有 seed 案件叫修日期多為 `2026-07-08`。為讓「預設查當日」規格在進頁面時即有資料可展示，將於 `data.js` **補上數筆叫修日期為今日的 seed 案件**（涵蓋未結案／結案、含／不含設備資料），使進頁面預設查當日即顯示列表；同時保留舊日期案件供調整日期區間時查詢。
