# 案件日期欄位（叫修／再次叫修／完工）Demo 設計文件

**日期：** 2026-07-10  
**範圍：** 於「案件處理」編輯視窗與「叫修案件紀錄」查看明細視窗，新增三個日期欄位顯示；並在儲存處理狀態時依規則自動押日期  
**風格／技術：** 沿用既有戰情室 demo（原生 HTML / CSS / JS，記憶體假資料）

---

## 1. 目標與成功標準

在「案件處理」與「叫修案件紀錄」的案件視窗中，顯示：

- 叫修日期
- 再次叫修日期
- 完工日期

並讓「案件處理」儲存編輯時，依處理狀態自動寫入對應日期（不清空既有值）。

成功標準：

- 兩處視窗皆可見上述三個日期（唯讀）
- Seed 假資料依處理狀態補齊合理日期
- 儲存時依連動規則押日期；轉汰換／轉原廠不寫入日期
- 不做「回到工作排程」「新建工程」提示或導頁

---

## 2. 資料欄位

| 欄位 | key | 格式 | 說明 |
|------|-----|------|------|
| 叫修日期 | `repairDate`（既有） | `YYYY-MM-DD` | 建立案件時寫入；不因處理狀態改動 |
| 再次叫修日期 | `reRepairDate`（新增） | `YYYY-MM-DD` 或 `""` | 依處理狀態自動押上；不清空模式 |
| 完工日期 | `completionDate`（新增） | `YYYY-MM-DD` 或 `""` | 依處理狀態自動押上；不清空模式 |

新建案件時：`reRepairDate`、`completionDate` 初始為 `""`。

---

## 3. 處理狀態連動邏輯（不清空）

在「案件處理」儲存編輯時，依當下 `processStatus` 套用：

| 處理狀態 | `reRepairDate` | `completionDate` |
|----------|----------------|------------------|
| 待料、待報價、尚未完成 | 押今天 | 保留原值（不清空） |
| 案件完成 | 保留原值（不清空） | 押今天 |
| 轉汰換、轉原廠 | 不寫入（維持原值） | 不寫入（維持原值） |

規則摘要：

- **只寫入、不清空**：從不主動把既有日期清成空字串
- 自動押的日期值一律為「今天」（`YYYY-MM-DD`）
- 不做「回到工作排程」「新建工程」文字提示

共用 helper（建議放在 `data.js`）：

```js
applyProcessStatusDates(caseData, processStatus, todayStr)
```

行為：

- 若狀態 ∈ {待料, 待報價, 尚未完成} → 回傳 `{ ...caseData, reRepairDate: todayStr }`（其餘日期欄位原樣）
- 若狀態 === 案件完成 → 回傳 `{ ...caseData, completionDate: todayStr }`
- 若狀態 ∈ {轉汰換, 轉原廠} → 回傳原物件（不改日期）
- 其他狀態（若有）→ 不改日期

## 4. UI 顯示

### 4.1 案件處理 — 編輯案件 Modal

- 位置：「案件資訊」區塊
- 新增三個**唯讀**欄位（順序）：叫修日期、再次叫修日期、完工日期
- 空值顯示空白或 `—`
- 使用者不可手動編輯這三個日期；僅能透過處理狀態儲存連動寫入
- 列表表格不新增這三欄

### 4.2 叫修案件紀錄 — 查看明細 Modal

- 位置：「案件資料」段（建議靠近案件編號）
- 同樣顯示三個日期（唯讀），空值顯示 `—`
- 「處理資料」段維持既有欄位（含處理狀態）

## 5. Seed 假資料對齊

於 `SEED_CASES` 每筆補上 `reRepairDate`、`completionDate`，依該筆 `processStatus` 給合理值，例如：

- 待料／待報價／尚未完成：`reRepairDate` 有值（可為叫修日之後或同日），`completionDate` 可為 `""`
- 案件完成：`completionDate` 有值；`reRepairDate` 可有可無（示範保留）
- 轉汰換／轉原廠：兩者皆可為 `""`（示範「不寫入」）

不刪除既有案件；僅補欄位。
